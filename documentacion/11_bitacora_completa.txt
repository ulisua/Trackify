=====================================================================
  BITÁCORA SEMANAL DE AVANCES DEL PROYECTO — TRACKIFY
=====================================================================

Registro Obligatorio — Completar cada semana antes del próximo
encuentro presencial.
La bitácora es una evidencia del proceso de trabajo del equipo. Debe
actualizarse semana a semana, registrando los avances técnicos
concretos, los riesgos detectados en esa iteración del Modelo en
Espiral y las acciones correctivas planificadas. El docente la
revisará al inicio de cada clase.

CÓMO COMPLETARLA: Cada integrante puede aportar a la descripción de
avances técnicos. El Team Lead es responsable de asegurarse de que
esté completo antes del próximo encuentro. Usar lenguaje técnico
preciso.

Nota de esta versión: el texto que ya estaba se mantuvo; se agregaron
los cambios de cada commit del repositorio (todas las ramas). Cada
commit se asignó a la clase más cercana (del sábado anterior al
viernes posterior). Las semanas sin commits se indican como tales.

  funciones. Investigamos con ayuda de la IA para saber por dónde
  empezar. Asistidos por la IA, logramos consolidar el orden,

Sem 5 — 09/04/2026
---------------------------------------------------------------------
Avances Técnicos:
  Debate grupal donde analizamos detalladamente cada área y su
  desarrollo hasta el momento, planeamos cómo evitar futuros errores y
  descartamos funciones que dificulten el desarrollo del software.
  Base de datos: En grupo, discutimos la forma más óptima de
  implementarla, descartamos ciertos rubros y diseñamos algunos que
  faltaban.
  Investigamos a nivel general, en qué estado se encuentra el proyecto
  y la documentación, completamos la sección de definiciones de clase.
  Con ayuda de la IA corregimos la estructura de las tablas de base de
  datos.
  Vinculación del repositorio de Git con el repositorio local del
  software y simplificación del código frontend.
  Empezamos el código backend y completamos el "LOGIN" y registro.
  Commit "Registro y login terminado" (09/04): conexion.php,
  login.php, registro.php y logout.php funcionales contra MySQL.
Riesgos Identificados:
  Como riesgos identificados encontramos problemas para utilizar la
  página si el usuario es extranjero, incompatibilidad de monedas.
  Probable error en la base de datos sobre la tabla "categoría de
  gastos" y "moneda". Revisamos que la base de datos y el frontend
  presente una concordancia en cuanto a citado de datos.
  Consulta de la IA sobre detalles de cómo manejar la clave de usuario
  en la base de datos.
  Problema para administrar las claves de cada usuario. Encontramos
  incompatibilidades con MYSQL.
Acciones Correctivas:
  Consultamos con la IA como podemos integrar en la base de datos la
  moneda de un par de países (dólar y peso), bocetos de distintas
  formas de distribuir las opciones de forma óptima para que el
  usuario seleccione la moneda de preferencia.
  Corregimos, simplificamos y optimizamos el estado de la DB y
  funciones del frontend.
  Probamos distintas alternativas y tutoriales sobre la clave.
  Instalamos otro programa de base de datos, PGAdmin.
