=====================================================================
  TRACKIFY — CÓMO MIGRAR LA BASE DE DATOS DE MYSQL A POSTGRESQL
=====================================================================

Resumen: el cambio tiene tres partes.
  A. Crear el esquema en PostgreSQL (los tipos no son iguales).
  B. Pasar los datos.
  C. Adaptar el código PHP: hoy usa la extensión mysqli, que SOLO
     funciona con MySQL. Hay que pasar a PDO (sirve para los dos
     motores) y corregir las consultas con sintaxis propia de MySQL.

Esfuerzo estimado: 2 a 4 días de una persona. Afecta 22 archivos PHP
(todos los que usan $conn).

Recomendación: hacerlo en una rama aparte (por ejemplo
"feature/postgresql") y no mezclarlo con otros cambios.


---------------------------------------------------------------------
PASO 0 — PREPARAR EL ENTORNO
---------------------------------------------------------------------
1. Instalar PostgreSQL 16 (incluye pgAdmin) desde postgresql.org.
   XAMPP no trae PostgreSQL.
2. Habilitar el driver en PHP: en C:\xampp\php\php.ini descomentar
     extension=pdo_pgsql
     extension=pgsql
   y reiniciar Apache. Verificar con phpinfo() que aparezca "pdo_pgsql".
3. Crear la base y un usuario (en psql o en pgAdmin):
     CREATE USER trackify WITH PASSWORD 'una_clave';
     CREATE DATABASE trackify OWNER trackify ENCODING 'UTF8';
4. Agregar al .env (y a .env.example, sin la clave):
     DB_DRIVER=pgsql
     DB_HOST=localhost
     DB_PORT=5432
     DB_USER=trackify
     DB_PASS=una_clave
     DB_NAME=trackify
5. Hacer un respaldo de MySQL antes de empezar:
     phpMyAdmin > Exportar  (o)  mysqldump -u root trackify > respaldo.sql


---------------------------------------------------------------------
PASO A — EQUIVALENCIAS DE TIPOS
---------------------------------------------------------------------
  MySQL                          PostgreSQL
  -----------------------------  ------------------------------------
  INT AUTO_INCREMENT             INTEGER GENERATED ALWAYS AS IDENTITY
                                 (o SERIAL)
  TINYINT(1)                     BOOLEAN
  ENUM('ingreso','gasto')        VARCHAR + CHECK, o CREATE TYPE ... AS ENUM
  DECIMAL(12,2)                  NUMERIC(12,2)
  VARCHAR(n), TEXT, DATE         iguales
  DATETIME                       TIMESTAMP
  TIMESTAMP ... ON UPDATE        TIMESTAMP + trigger (no existe ON UPDATE)
  `nombre` (backticks)           "nombre" (comillas dobles) o sin comillas
  ENGINE=InnoDB, CHARSET=...     no existen: se borran
  UNIQUE KEY x (col)             UNIQUE (col) / CREATE UNIQUE INDEX
  KEY x (col)                    CREATE INDEX x ON tabla (col)

OJO con mayúsculas: PostgreSQL pasa a minúscula todo nombre sin
comillas. La columna "Foto_perfil" conviene renombrarla a foto_perfil
(y cambiarla en registro.php, auth/google/callback.php y conexion.php).


---------------------------------------------------------------------
PASO A.1 — ESQUEMA EN POSTGRESQL (trackify_pg.sql)
---------------------------------------------------------------------
Se usan CHECK en lugar de ENUM porque son más fáciles de modificar.

CREATE TABLE usuarios (
    id_usuario          INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nombre              VARCHAR(50)  NOT NULL,
    nombre_usuario      VARCHAR(30)  UNIQUE,
    email               VARCHAR(100) NOT NULL UNIQUE,
    clave               VARCHAR(255) NOT NULL,
    fecha_registro      TIMESTAMP    NOT NULL,
    uuid                VARCHAR(255),
    foto_perfil         VARCHAR(255),
    google_id           VARCHAR(255),
    email_verificado    BOOLEAN      NOT NULL DEFAULT FALSE,
    codigo_verificacion VARCHAR(10),
    codigo_expiracion   TIMESTAMP,
    moneda_principal    VARCHAR(3)   NOT NULL DEFAULT 'ARS'
                        CHECK (moneda_principal IN ('ARS','USD'))
);

CREATE TABLE categorias (
    id_categoria INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_usuario   INTEGER,                 -- NULL = categoría del sistema
    nombre       VARCHAR(50) NOT NULL,
    tipo         VARCHAR(7)  NOT NULL CHECK (tipo IN ('ingreso','gasto')),
    icono        VARCHAR(255),
    color        VARCHAR(7)
);
CREATE INDEX idx_categorias_usuario ON categorias (id_usuario);

CREATE TABLE movimientos (
    id_movimiento INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_usuario    INTEGER NOT NULL REFERENCES usuarios (id_usuario),
    id_categoria  INTEGER NOT NULL REFERENCES categorias (id_categoria),
    monto         NUMERIC(12,2) NOT NULL,
    tipo          VARCHAR(7) NOT NULL CHECK (tipo IN ('ingreso','gasto')),
    descripcion   VARCHAR(255),
    fecha         DATE NOT NULL,
    es_hormiga    BOOLEAN DEFAULT FALSE
);
CREATE INDEX idx_movimientos_usuario   ON movimientos (id_usuario);
CREATE INDEX idx_movimientos_categoria ON movimientos (id_categoria);

CREATE TABLE metas_ahorro (
    id_meta        INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_usuario     INTEGER REFERENCES usuarios (id_usuario),
    nombre_meta    VARCHAR(100) NOT NULL,
    descripcion    VARCHAR(255),
    monto_objetivo NUMERIC(12,2) NOT NULL,
    monto_actual   NUMERIC(12,2) NOT NULL DEFAULT 0,
    fecha_limite   DATE NOT NULL,
    estado         VARCHAR(8) DEFAULT 'activo'
                   CHECK (estado IN ('activo','inactivo','logrado'))
);
CREATE INDEX idx_metas_usuario ON metas_ahorro (id_usuario);

CREATE TABLE consejos_ia (
    id_consejos INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_usuario  INTEGER REFERENCES usuarios (id_usuario),
    mensaje     TEXT NOT NULL,
    fecha       TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
-- En MySQL "fecha" tenía ON UPDATE CURRENT_TIMESTAMP. Si se necesita:
-- crear una función + trigger BEFORE UPDATE que haga NEW.fecha := now().

Se usa "BY DEFAULT" (y no "ALWAYS") para poder insertar los ids que
ya existen al copiar los datos.


---------------------------------------------------------------------
PASO B — PASAR LOS DATOS
---------------------------------------------------------------------
Opción 1 (recomendada): pgloader, que convierte tipos solo.
  pgloader mysql://root@localhost/trackify postgresql://trackify:clave@localhost/trackify
  (En Windows se usa con Docker: docker run --rm dimitri/pgloader ...)
  Después revisar que TINYINT haya quedado como BOOLEAN y los nombres
  en minúscula.

Opción 2 (manual, para una base chica como la nuestra):
  1. Crear las tablas con trackify_pg.sql (Paso A.1).
  2. En phpMyAdmin exportar SOLO DATOS como CSV, tabla por tabla.
  3. En psql, en este orden (por las FK):
       \copy usuarios     FROM 'usuarios.csv'     CSV HEADER
       \copy categorias   FROM 'categorias.csv'   CSV HEADER
       \copy movimientos  FROM 'movimientos.csv'  CSV HEADER
       \copy metas_ahorro FROM 'metas_ahorro.csv' CSV HEADER
       \copy consejos_ia  FROM 'consejos_ia.csv'  CSV HEADER
     (email_verificado y es_hormiga vienen como 0/1: PostgreSQL acepta
     '0'/'1' para BOOLEAN en COPY.)

Paso obligatorio después de copiar: reajustar los contadores de ids,
si no, el próximo INSERT choca con un id existente.
  SELECT setval(pg_get_serial_sequence('usuarios','id_usuario'),
                (SELECT MAX(id_usuario) FROM usuarios));
  -- repetir para categorias, movimientos, metas_ahorro, consejos_ia

Verificar: SELECT COUNT(*) de cada tabla en ambos motores debe
coincidir.


---------------------------------------------------------------------
PASO C — ADAPTAR EL CÓDIGO PHP
---------------------------------------------------------------------

C.1  Cambiar la conexión (conexion.php)
     Antes:
       $conn = new mysqli(env('DB_HOST'), env('DB_USER'), env('DB_PASS'), env('DB_NAME'));
       $conn->set_charset('utf8mb4');
     Después:
       $dsn = sprintf('pgsql:host=%s;port=%s;dbname=%s',
                      env('DB_HOST','localhost'), env('DB_PORT','5432'), env('DB_NAME','trackify'));
       $conn = new PDO($dsn, env('DB_USER'), env('DB_PASS'), [
           PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
           PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
       ]);
     El catch pasa de mysqli_sql_exception a PDOException (también en
     movimientos_handler.php, objetivos.php y categorias.php).

C.2  Reemplazar el patrón mysqli por PDO (en los 22 archivos)
     mysqli                                  PDO
     --------------------------------------  ------------------------------
     $stmt = $conn->prepare($sql)            igual
     $stmt->bind_param("si", $a, $b)         (se elimina)
     $stmt->execute()                        $stmt->execute([$a, $b])
     $stmt->get_result()->fetch_assoc()      $stmt->fetch()
     ->get_result()->fetch_all(MYSQLI_ASSOC) $stmt->fetchAll()
     $conn->query($sql)->fetch_assoc()       $conn->query($sql)->fetch()
     $conn->insert_id                        $conn->lastInsertId()  (*)
     $stmt->affected_rows                    $stmt->rowCount()
     $conn->begin_transaction()              $conn->beginTransaction()
     $conn->commit() / rollback()            iguales
     $result->num_rows                       count($stmt->fetchAll()) o SELECT COUNT(*)

     (*) En PostgreSQL es más seguro usar RETURNING:
         INSERT INTO usuarios (...) VALUES (...) RETURNING id_usuario
         $id = $stmt->fetchColumn();
         Lugares: registro.php y includes/categorias_meta.php.

     Consejo: crear una función auxiliar en conexion.php
       function db($sql, array $params = []) {
           global $conn; $s = $conn->prepare($sql); $s->execute($params); return $s;
       }
     y reemplazar de a un archivo, probando cada pantalla.

C.3  Consultas con sintaxis propia de MySQL (encontradas en el código)

     index.php e ia.php — agrupar por mes:
       MySQL:  DATE_FORMAT(fecha, '%Y-%m')
       PG:     TO_CHAR(fecha, 'YYYY-MM')

       MySQL:  fecha >= DATE_FORMAT(CURDATE() - INTERVAL 5 MONTH, '%Y-%m-01')
       PG:     fecha >= DATE_TRUNC('month', CURRENT_DATE - INTERVAL '5 months')

       MySQL:  fecha >= DATE_FORMAT(CURDATE(), '%Y-%m-01')
       PG:     fecha >= DATE_TRUNC('month', CURRENT_DATE)

     perfil.php e ia.php:
       CURDATE()  ->  CURRENT_DATE

     registro.php:
       NOW()      ->  NOW()   (igual en PG)

     conexion.php — categorías iniciales:
       MySQL:  INSERT IGNORE INTO categorias ...
       PG:     INSERT INTO categorias ... ON CONFLICT DO NOTHING
               (requiere una restricción UNIQUE, por ejemplo
               UNIQUE (nombre, tipo, id_usuario); si no, verificar
               antes con SELECT).

     conexion.php — chequeo de columnas:
       MySQL:  WHERE TABLE_SCHEMA = DATABASE()
       PG:     WHERE table_schema = current_schema()
       MySQL:  NUMERIC_SCALE ...       PG: numeric_scale (minúscula)

     conexion.php — migraciones:
       "ALTER TABLE x ADD COLUMN IF NOT EXISTS ..."  -> funciona igual en PG
       "ALTER TABLE usuarios ADD UNIQUE INDEX IF NOT EXISTS uq (col)"
          -> "CREATE UNIQUE INDEX IF NOT EXISTS uq ON usuarios (col)"
       "ADD INDEX IF NOT EXISTS idx (col)"
          -> "CREATE INDEX IF NOT EXISTS idx ON categorias (col)"
       "MODIFY monto_objetivo DECIMAL(12,2)"
          -> "ALTER COLUMN monto_objetivo TYPE NUMERIC(12,2)"
       Con el esquema nuevo ya completo, se puede simplificar todo este
       bloque.

     Booleanos (email_verificado, es_hormiga):
       En MySQL se compara con 0/1. En PG usar TRUE/FALSE:
         WHERE email_verificado = 1  ->  WHERE email_verificado = TRUE
         SET email_verificado = 1    ->  SET email_verificado = TRUE
       Al leerlos, PDO devuelve true/false (no "1"/"0"): revisar los if.

     Comparaciones de texto:
       MySQL (utf8mb4_general_ci) NO distingue mayúsculas: 'Juan' = 'juan'.
       PostgreSQL SÍ distingue. Revisar búsquedas por email y por
       nombre de categoría: usar LOWER(email) = LOWER(?) o guardar el
       email siempre en minúscula. Igual para LIKE -> ILIKE.

     GROUP BY:
       PG es estricto: toda columna del SELECT que no esté en una
       función de agregado debe estar en el GROUP BY. Las consultas de
       index.php e ia.php ya agrupan por id y nombre, pero hay que
       probarlas.

     Comillas:
       Si alguna consulta usa `backticks`, quitarlos.

C.4  Montos
     PDO devuelve NUMERIC como string ("1500.00"). Donde se hagan
     cuentas en PHP, convertir con (float). number_format() ya lo hace.

ALTERNATIVA DE MENOR RIESGO
---------------------------------------------------------------------
Hacer primero SOLO el Paso C.2 (mysqli -> PDO) manteniendo MySQL. PDO
funciona igual con MySQL, así que se puede probar todo sin cambiar de
motor. Después, cambiar de motor es solo modificar el DSN, el esquema
y las consultas del Paso C.3.


---------------------------------------------------------------------
¿VALE LA PENA?
---------------------------------------------------------------------
A favor de PostgreSQL: CHECK y tipos más estrictos, mejor manejo de
fechas, hostings gratuitos que lo ofrecen (Supabase, Neon, Render).
En contra: XAMPP no lo trae, el equipo ya domina MySQL/phpMyAdmin y en
la Sem 6 ya se intentó con dificultades. Si el objetivo es solo
hostear la app, también existen hostings con MySQL; la migración se
justifica si el hosting elegido solo ofrece PostgreSQL.
