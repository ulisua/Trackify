3. UML — SECUENCIA: REGISTRO Y VERIFICACIÓN DE EMAIL
=====================================================================

sequenceDiagram
    actor U as Usuario
    participant N as Navegador
    participant R as registro.php
    participant BD as MySQL
    participant ML as mailer.php
    participant S as Servidor SMTP
    participant V as verificar_email.php

    U->>N: Completa nombre, email, contraseña
    N->>R: POST /registro.php
    R->>R: Valida datos, password_hash(), generarUuid()
    R->>BD: INSERT usuarios (email_verificado = 0)
    R->>ML: iniciarVerificacionEmail()
    ML->>BD: UPDATE codigo_verificacion, codigo_expiracion (+15 min)
    ML->>S: Envía email con código de 6 dígitos
    R-->>N: Redirect a verificar_email.php
    S-->>U: Email con el código
    U->>N: Ingresa el código
    N->>V: POST código
    V->>BD: SELECT codigo, expiracion
    alt Código correcto y vigente
        V->>BD: UPDATE email_verificado = 1, borra código
        V-->>N: Inicia sesión, redirect a index.php
    else Código incorrecto / vencido (máx. 5 intentos)
        V-->>N: Mensaje de error
    end

4. UML — SECUENCIA: CONSULTA AL ASISTENTE IA
=====================================================================

sequenceDiagram
    actor U as Usuario
    participant JS as js/ia.js
    participant IA as ia.php
    participant BD as MySQL
    participant G as API Groq

    U->>JS: Escribe una pregunta
    JS->>IA: POST JSON {pregunta, historial} + X-CSRF-Token
    IA->>IA: Verifica sesión, CSRF, largo y límite de 2 s
    IA->>BD: SELECT totales por mes, gastos por categoría, metas
    BD-->>IA: Datos del usuario
    IA->>G: POST chat/completions (sistema + contexto + pregunta)
    G-->>IA: Respuesta generada
    IA-->>JS: JSON {respuesta}
    JS-->>U: Muestra la respuesta en el chat

5. UML — SECUENCIA: APORTE Y ELIMINACIÓN DE UN OBJETIVO
=====================================================================

sequenceDiagram
    actor U as Usuario
    participant O as objetivos.php
    participant BD as MySQL

    U->>O: POST aporte (monto en ARS)
    O->>BD: BEGIN
    O->>BD: UPDATE metas_ahorro SET monto_actual = monto_actual + monto
    O->>BD: INSERT movimientos (gasto, "Ahorro para meta")
    O->>BD: COMMIT
    O-->>U: Redirect + aviso

    U->>O: POST eliminar objetivo
    O->>BD: BEGIN
    O->>BD: INSERT movimientos (ingreso, "Reintegro de meta", monto_actual)
    O->>BD: DELETE metas_ahorro
    O->>BD: COMMIT
    O-->>U: Redirect + aviso

6. UML — ACTIVIDADES: CARGAR UN MOVIMIENTO
=====================================================================

flowchart TD
    A([Inicio]) --> B[Abrir modal + Ingreso / + Gasto]
    B --> C[Ingresar monto, moneda, categoría, fecha, descripción]
    C --> D{¿Monto > 0?}
    D -- No --> C
    D -- Sí --> E{¿Moneda USD?}
    E -- Sí --> F{¿Hay cotización?}
    F -- No --> G[Avisar y no enviar] --> C
    F -- Sí --> H[Convertir a ARS]
    E -- No --> I[Enviar formulario]
    H --> I
    I --> J{Servidor: CSRF, monto, fecha y categoría válidos?}
    J -- No --> K[Mensaje de error] --> L
    J -- Sí --> M[INSERT en movimientos] --> N[Mensaje de éxito] --> L
    L[Redirigir a la página de origen] --> Z([Fin])

9. DER — DIAGRAMA ENTIDAD-RELACIÓN
=====================================================================

erDiagram
    USUARIOS ||--o{ MOVIMIENTOS : "registra"
    USUARIOS ||--o{ METAS_AHORRO : "define"
    USUARIOS ||--o{ CONSEJOS_IA : "recibe"
    USUARIOS |o--o{ CATEGORIAS : "crea (NULL = del sistema)"
    CATEGORIAS ||--o{ MOVIMIENTOS : "clasifica"

    USUARIOS {
        int id_usuario PK
        varchar nombre
        varchar nombre_usuario UK
        varchar email UK
        varchar clave
        datetime fecha_registro
        varchar uuid
        varchar Foto_perfil
        varchar google_id
        tinyint email_verificado
        varchar codigo_verificacion
        datetime codigo_expiracion
        enum moneda_principal
    }
    MOVIMIENTOS {
        int id_movimiento PK
        int id_usuario FK
        int id_categoria FK
        decimal monto
        enum tipo
        varchar descripcion
        date fecha
        tinyint es_hormiga
    }
    CATEGORIAS {
        int id_categoria PK
        int id_usuario "índice, sin FK"
        varchar nombre
        enum tipo
        varchar icono
        varchar color
    }
    METAS_AHORRO {
        int id_meta PK
        int id_usuario FK
        varchar nombre_meta
        varchar descripcion
        decimal monto_objetivo
        decimal monto_actual
        date fecha_limite
        enum estado
    }
    CONSEJOS_IA {
        int id_consejos PK
        int id_usuario FK
        text mensaje
        timestamp fecha
    }
